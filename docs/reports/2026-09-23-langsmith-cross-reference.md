The scope is the behavior report's fixed snapshot at **2026-09-23 20:40:32.814900+00:00**. All **35 best/excellent/good runs**, containing **310 passes**, were matched. **How the match was verified**

The positional runner passes the database run UUID as the harness `game_id`. LangSmith records that exact UUID in both `metadata.game_id` and `metadata.thread_id`. This is an identifier join, not a match based only on similar moves or timestamps.

For every exported run and pass, the checks confirmed:

- Exact database run UUID in the root and model-span metadata.
- Root canonical FEN equal to the saved position FEN.
- Equal counts of database passes and LangSmith LLM spans.
- Each model call occurring entirely inside its corresponding database pass time interval.
- Exact agreement between notes extracted from the recorded response and the PostgreSQL working-note string.
- Exact agreement between the response’s parsed tool requests and the stored tool names, arguments, and call IDs.
- Recorded request and response content present for every matched pass.

**What each exported pass contains**

Each per-run JSONL file has one row per model pass. It contains the original traced request (`model_request`), including developer/user messages, model name, reasoning setting, and output-token limit; the original traced response (`model_response`); extracted assistant text and API-exposed reasoning; PostgreSQL working notes and tool results; classification and CP/expected-points loss; pass status/errors; trace/span IDs and direct links; prompt hashes; and the match checks.

LangSmith explicitly labels **64** of these calls as forced tool retries. **286** contain API-exposed reasoning, and **0** have no assistant message text. A response can contain reasoning without a valid tool block; these unsuccessful passes are retained with their database failure status.

Recorded response-status counts: `{"completed": 350}`. The number of distinct developer-message hashes is **1** across the selected calls. In this export, all 350 developer messages are identical. The export preserves the actual message from each call rather than assuming the shared prompt-version label proves identical prompts.

“Original” here means the content preserved by the LangSmith SDK. It is not a network-packet capture: for example, the wrapper normalizes usage information into `usage_metadata`. API-exposed reasoning is included where returned; no claim is made to recover anything the provider did not expose. A complete trace record also does not imply the model completed a valid response within its token budget.
