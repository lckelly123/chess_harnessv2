# Chess research workspace

- Scope: the local React interface in `frontend/`; visitor mode is Operate. Match desk, Match library, and Positional testing are separate destinations in one persistent workspace shell.
- Audience and job: a harness developer watches matches, inspects a selected ply, revisits historical runs, or requests one move from a saved PGN position.
- Authority: the user pinned a modern black and purple redesign and delegated the remaining choices. The designer selected the analysis-workbench composition. Code is the system evidence; this pass created no separate concept card or visual comp.
- Direction: near-black graphite surfaces, violet actions and selections, lavender board squares, Archivo text, and one-pixel divisions. Root `DESIGN.md` and `.impeccable/design.json` replace the former cream/green ledger identity.
- First viewport: slim desktop navigation, complete board and replay transport, then selected explanation above compact chronology. New match expands setup; setup opens automatically when no match is selected. Historical browsing has its own library destination.
- Primary actions: choose white and black harnesses and a folder; start or stop a match; replay, scrub, and flip the board; select a trace ply; search, open, and refile records; create folders; select a saved position and harness; request one positional move.
- Harness choices: Baseline, Agent Player 1, Agent Player 2, and Agent Player 3. Positional testing resolves the four configured versioned IDs against the API and reports missing choices. Shared model controls stay in the shell and lock during a positional run.
- Content: typed harness, model, folder, match, position, player, trace, saved-PGN, and one-turn-result data from the existing FastAPI API. Saved positions come from `backend/positional_testing/positions`; IDs and versions remain inspectable.
- Signature interaction: selecting a trace event selects its ply, synchronizes board and inspector, pauses playback, and enters replay mode. The inspector prefers the completed move event at that ply, then another move event, then the latest event. It presents the recorded explanation and disclosures for metadata and other events at that ply.
- Trace completeness: Moves and All events filters preserve ply groups. Every event remains accessible with timestamp, ply, player, phase, status, summary, stable ID, and recorded detail. Missing explanations have explicit empty states. Internal scrolling brings the selected group into view without moving the page or fighting routine polling.
- Library behavior: folders and search narrow historical matches. Opening a record returns to Match desk for replay. Folder reassignment and pending/error feedback stay local to that row. Harness versions unfold separately from the open action.
- Positional behavior: a saved-position index leads to the board, four supported harness choices, run command, and transient response. The component stays mounted while navigation hides it, preserving selection, in-flight request, and result. Loading, empty, unavailable, missing-harness, running, error, retry, and completed states are explicit. Position and harness selections lock during a run. Success outlines the proposed path on the unchanged board and shows violet SAN, resolved model, justification, and available phase reports.
- Constraints: the backend owns state and legal moves. React exposes no human move controls or inferred hidden reasoning. Folders are organizational metadata. A positional response creates no match record and never mutates the saved PGN. Detailed graph execution remains in LangSmith.
- Responsive behavior: below 1250px the positional index becomes horizontal; below 1000px navigation moves above content; below 760px board/analysis and positional board/controls stack and indexes scroll horizontally; below 480px setup, records, and replay reflow further. Explanation and trace regions remain bounded, metadata wraps, and focus stays visible.
- Motion: brief color feedback, a small explanation entrance, and loading spinners; reduced-motion preference disables transitions and animation.
- Review evidence: final desktop, laptop, library, positional, and three mobile screenshots are under `.impeccable/review/final-*.png`. The parent implementation workflow reported a passing build, lint, eight tests, and an independent rendered finish review. This documentation pass records that evidence; no live model match or positional request was run for the redesign validation.
- Unresolved: snapshots still use polling and positional runs wait for a synchronous HTTP response; these existing transport limits remain unchanged.
